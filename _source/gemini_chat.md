4. Section 3: Deductive / Logical Reasoning (Actual Questions & Explanations)

Question 1 (Conversion Logic / Syllogism)
Premise: "Some of the employees who work day shifts also work double shifts."

Options:

A) All employees who work day shifts also work double shifts.

B) Some employees who work day shifts do not work double shifts.

C) None of the employees who work day shifts also work double shifts.

D) Some of the employees who work double shifts also work day shifts.

Correct Answer: Option D

Logical Rule Explained in Video:
Premise form hai: "Some A are B" . Formal deductive logic mein set intersection symmetric hota hai (A∩B=B∩A). Iska valid immediate inference hamesha "Some B are A" hota hai .

(Note: Option B common sense se sahi lag sakta hai, lekin formal logic mein "Some A are B" se "Some A are not B" strictly guarantee nahi hota, kyunki All A could potentially be B).

Question 2 (Conditional Logic & The Contrapositive Trap)
Premise: "All senior managers are required to attend a quarterly strategic meeting."   

Options:   

A) Everyone attending the strategic meeting is a senior manager. (False: others might attend)   

B) Anyone who is not a senior manager is not required to attend. (False: non-managers may also be required)   

C) Anyone who is required to attend the meeting is a senior manager. (False: Converse error)   

D) Anyone who is not required to attend the quarterly strategy meeting is not a senior manager.

Correct Answer: Option D

Logical Rule Explained in Video:
Statement format hai: P⟹Q (If Senior Manager ⟹ Required to attend) .

Converse (Q⟹P) zaroori nahi true ho.

Inverse (¬P⟹¬Q) zaroori nahi true ho.

Contrapositive (¬Q⟹¬P) strictly guaranteed true hota hai: Agar koi person meeting attend karne ke liye required nahi hai, to wo senior manager ho hi nahi sakta !

Deductive Reasoning Rules Cheat Sheet
Given Premise	Valid Deductive Conclusion	Invalid Fallacies to Avoid
All A are B	Some B are A OR If not B, then not A	All B are A (False)
No A are B	No B are A OR Some A are not B	Some A are B (False)
Some A are B	Some B are A	Some A are not B (Cannot guarantee)
P→Q	¬Q→¬P (Contrapositive)	Q \rightarrow P (Converse fallacy)

2. Problem Statement: Jump Game I
Problem Description
Aapko ek integer array nums diya gaya hai . Aap initially array ke first index (0) par khade hain .

Array ka har element nums[i] represent karta hai ki aap us index se maximum kitne steps aage jump kar sakte hain .

Agar aap array ke last index (nums.size() - 1) par pahunch sakte hain ya uske aage nikal sakte hain, to true return karein .

Agar last index tak pahunchna impossible ho, to false return karein .

4. Core Greedy Logic (O(N) Time, O(1) Space)
Ek variable maintain karte hain: maxReach = 0, jo batata hai ki hum array mein maximum kis index tak ab tak pahunch sakte hain .

Array ko index i=0 se scan karte hain :

Reachability Check: Agar current index i>maxReach ho jaye, iska matlab hum current index i par kabhi pahunch hi nahi sake the → Turant return false .

Update Reach: maxReach = max(maxReach, i + nums[i]) .

Early Exit Optimization: Agar kisi bhi step par maxReach >= n - 1 ho jaye, to aage loop chalaye bina turant return true kar sakte hain .

Jump Game II (Find Minimum Jumps to reach the end) ka greedy solution aur common buggy codes samjhaiye.

Yeh problem LeetCode 45 (Jump Game II) hai. Jump Game I mein sirf yeh check karna tha ki last index tak pahunch sakte hain ya nahi (true/false), jabki Jump Game II mein last index tak pahunchna guaranteed hota hai aur minimum jumps count karne hote hain.

1. Core Intuition & Mathematical Logic (BFS as Greedy)
Isko O(N) mein solve karne ka tarika Range-Based Greedy (ya implicit 1D BFS) hai:

Hum array ko jump ranges/levels mein divide karte hain:

Level 0: [0..0] (Start position, jumps = 0)

Level 1: Index 0 se jahan tak ja sakte hain [1..currentEnd] (jumps = 1)

Level 2: Level 1 ke kisi bhi point se jahan tak furthest ja sakte hain (jumps = 2)

Two Pointer / Boundary Variables:

farthest: Current window ke sabhi indices se aage tak ka maximum reach track karta hai:

farthest=max(farthest,i+nums[i])
currentEnd: Current jump ka end point. Jab loop pointer i chalte-chalte currentEnd par pahunchta hai, iska matlab ek jump exhaust ho gayi:

jumps++

currentEnd = farthest

The Loop Boundary Trap: Loop n−1 tak kyu chalta hai?
Loop strictly i<n−1 tak chalna chahiye (last index n−1 ko visit nahi karna hai).

Kyu? Agar hum last index par pahunch gaye, to hume wahan se koi nayi jump lene ki zaroorat nahi hoti. Agar loop i=n−1 par bhi chal gaya, to wo ek extra unnecessary jump increment kar dega!

3. Identified Bugs & Step-by-Step Fixes
Loop Boundary Off-by-One (i < n vs i < n - 1):

Trap: for (int i = 0; i < n; i++).

Impact: Jab i=n−1 (last index) par loop pahunchega aur i==currentEnd evaluate hoga, to jumps++ ho jayega. Jumps count actual answer se 1 zyada aayega.

Fix: Loop ko strictly i < n - 1 tak chalayein.

Reach Index vs Element Value (nums[i] vs i + nums[i]):

Trap: farthest = Math.max(farthest, nums[i]);.

Impact: nums[i] sirf jump ki length hai, absolute target index nahi.

Fix: Target index hamesha current_index + jump_length hota hai: farthest = Math.max(farthest, i + nums[i]);.

Single Element Edge Case (nums = [0] ya nums = [5]):

Trap: Agar array ka size 1 ho, to candidate already destination par khada hai, jumps required = 0.

Impact: Agar loop i<n−1 chalta hai to yeh natural tarike se 0 iterations chalega aur jumps = 0 dega, lekin agar code mein initialization ya loop check galat ho to yeh 1 return kar deta hai.

Early Exit Optimization (Speed Boost):

Jab bhi farthest >= n - 1 ho jaye, hum jumps + 1 return karke foran loop break kar sakte hain.

5. Final Verified Implementations
Java Solution (O(N) Time, O(1) Space)
Java
public class JumpGameTwo {
    public int jump(int[] nums) {
        if (nums == null || nums.length <= 1) {
            return 0; // Already at destination
        }

        int jumps = 0;
        int currentEnd = 0;
        int farthest = 0;
        int n = nums.length;

        // Loop stops at n - 2 to prevent redundant jump at the destination
        for (int i = 0; i < n - 1; i++) {
            // FIX 1: Add current index i to jump length
            farthest = Math.max(farthest, i + nums[i]);

            // FIX 2: Reached current jump boundary
            if (i == currentEnd) {
                jumps++;
                currentEnd = farthest;

                // Optimization: If current reach covers the last index, early break
                if (currentEnd >= n - 1) {
                    break;
                }
            }
        }

        return jumps;
    }
}

Java Implementation (O(N) Time, O(1) Space)
Java
public class GasStation {
    public int canCompleteCircuit(int[] gas, int[] cost) {
        int totalSurplus = 0;
        int currentTank = 0;
        int startStation = 0;

        for (int i = 0; i < gas.length; i++) {
            int net = gas[i] - cost[i];
            totalSurplus += net;
            currentTank += net;

            // If tank drops below zero, cannot reach station i + 1 from current start
            if (currentTank < 0) {
                startStation = i + 1; // Restart from the next station
                currentTank = 0;      // Reset current tank
            }
        }

        // If total gas collected across all stations is less than total cost, impossible
        return (totalSurplus < 0) ? -1 : startStation;
    }
}

3. Identified Bugs & Step-by-Step Fixes
Comparator Sorting Trap (a[1] - b[1] vs a[0] - b[0]):

Problem: End time se sort karne par order break ho jata hai (e.g., [[2, 3], [4, 5], [1, 10]]). Yahan [1, 10] end mein chala jayega aur beech ke intervals ko merge nahi kar payega.

Fix: Hamesha Start Time se sort karein: (a, b) -> Integer.compare(a[0], b[0]) (C++ mein sort(intervals.begin(), intervals.end()) default first element se hi sort karta hai).

Touching Intervals Boundary Trap (< vs <=):

Problem: Agar intervals [1, 4] aur [4, 5] hon, to 4≤4 true hona chahiye. Agar strict < use kiya, to code inhe non-overlapping maan kar alag-alag chhod dega jabki output [1, 5] hona chahiye.

Fix: Overlap condition strictly intervals[i][0] <= current[1] honi chahiye.

Subsumed / Enclosed Interval Trap (current[1] = next[1] vs Math.max):

Problem: Agar [1, 8] aur [2, 4] merge hon, to direct current[1] = next[1] likhne se naya end 4 ho jayega jo ki galat hai (8→4 shrink nahi ho sakta).

Fix: current[1] = Math.max(current[1], intervals[i][1]);.

Missing Final Interval Bug:

Problem: Loop khatam hone ke baad aakhri active interval (current) merged list mein add nahi hota, jisse result ka aakhri element gayab ho jata hai.

Fix: Loop ke bahar merged.add(current); lagayein.

Java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

public class MergeIntervals {
    public int[][] merge(int[][] intervals) {
        if (intervals == null || intervals.length <= 1) {
            return intervals;
        }

        // FIX 1: Sort by start time ascending
        Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));

        List<int[]> merged = new ArrayList<>();
        int[] current = intervals[0];

        for (int i = 1; i < intervals.length; i++) {
            // FIX 2: <= ensures touching intervals are merged
            if (intervals[i][0] <= current[1]) {
                // FIX 3: Preserve the furthest end boundary
                current[1] = Math.max(current[1], intervals[i][1]);
            } else {
                merged.add(current);
                current = intervals[i];
            }
        }

        // FIX 4: Append the last tracked interval
        merged.add(current);

        return merged.toArray(new int[merged.size()][]);
    }
}

C++
#include <vector>
#include <stack>
using namespace std;

vector<int> nextGreaterElement(vector<int>& arr) {
    int n = arr.size();
    vector<int> result(n);
    stack<int> st;

    // FIX 1: Iterate from right to left
    for (int i = n - 1; i >= 0; i--) {
        // FIX 2: Check !st.empty() before dereferencing st.top()
        while (!st.empty() && st.top() <= arr[i]) {
            st.pop();
        }

        // FIX 3: Assign -1 if no greater element exists to the right
        result[i] = st.empty() ? -1 : st.top();

        // Push current element for upcoming left elements
        st.push(arr[i]);
    }

    return result;
}

3. AI-Assisted Coding: Sliding Window Maximum (O(N) Monotonic Deque)
Capgemini ke AI coding round mein agar sliding window sum ke bajay Sliding Window Extreme (Max/Min) ka question aa jaye, to priority queue O(NlogK) dekar timeout ho jaati hai. Optimal solution Monotonic Deque se chalta hai:

Problem Statement
Array nums aur window size k diya gaya hai. Har window ka maximum element return karein as window slides from left to right.

Core Logic (O(N) Time, O(K) Space)
Ek double-ended queue (Deque) maintain karte hain jo indices store karti hai.

Monotonic Property: Deque ke andar values hamesha strictly decreasing rahengi:

Jab bhi naya element nums[i] aaye, deque ke peeche se un sabhi elements ko pop kar dein jo nums[i] se chhote ya barabar hain (kyunki jab tak nums[i] window mein hai, usse chhote purane elements kabhi max nahi ban sakte).

Window boundary se bahar hue indices (index <= i - k) ko front se remove karein.

Current window ka maximum hamesha deque ke front (deque.peekFirst()) par hota hai.

Java
import java.util.*;

public class SlidingWindowMax {
    public int[] maxSlidingWindow(int[] nums, int k) {
        if (nums == null || k <= 0) return new int[0];
        int n = nums.length;
        int[] result = new int[n - k + 1];
        int resIdx = 0;

        // Stores indices of useful elements in decreasing order of values
        Deque<Integer> deque = new ArrayDeque<>();

        for (int i = 0; i < n; i++) {
            // 1. Remove indices that are out of the current window bound [i - k + 1, i]
            while (!deque.isEmpty() && deque.peekFirst() <= i - k) {
                deque.pollFirst();
            }

            // 2. Remove smaller elements from back as they are useless
            while (!deque.isEmpty() && nums[deque.peekLast()] <= nums[i]) {
                deque.pollLast();
            }

            // 3. Push current index
            deque.offerLast(i);

            // 4. Record max once window of size k is formed
            if (i >= k - 1) {
                result[resIdx++] = nums[deque.peekFirst()];
            }
        }

        return result;
    }
}

# AI Literacy: High-Yield Case Studies & MCQs

### Question 1: Context Window Degradation & Token Truncation
**Scenario:** A customer service LLM bot functions well initially, but after 15 to 20 dialogue turns, it stops adhering to strict formatting guidelines (e.g., "always respond in 1 bullet point") configured in the initial system instructions. The system prompt itself has not been altered.
* **Options:**
  * A) The temperature parameter dynamically decreased due to user chat length.
  * B) The model has encountered catastrophic forgetting in its parameter weights.
  * C) Total cumulative tokens exceeded the model's effective context window, pushing earlier instructions out or weakening self-attention weight.
  * D) Vector embeddings experienced sparse retrieval collapse.
* **Correct Answer:** **C**
* **Technical Explanation:** Transformers calculate self-attention across tokens present within their active context window. As the dialogue grows, earlier system tokens are either truncated (dropped) or their relative positional attention weights decay.

---

### Question 2: Downstream JSON Parser Crashes
**Scenario:** An enterprise backend integrates an LLM to extract entity parameters. Despite prompting *"Output strictly valid JSON"*, the model periodically prefixes responses with conversational markdown like `Here is your JSON:\n```json`. This crashes the backend JSON parser.
* **Options:**
  * A) Increase the sampling temperature to 1.5.
  * B) Implement BNF grammar-based Guided Decoding / JSON Schema constraints at the inference engine level.
  * C) Switch from dense vector embeddings to BM25 sparse search.
  * D) Use Chain-of-Thought prompting with zero-shot triggers.
* **Correct Answer:** **B**
* **Technical Explanation:** Prompt-based instructions are probabilistic. Grammar-constrained decoding (e.g., JSON schema enforcement in OpenAI/vLLM APIs) restricts the model's token vocabulary at each sampling step to only tokens that form valid JSON grammar.

### Question 3: Retrieval Pipeline Splitting Safety Warnings (Chunking Failure)
**Scenario:** A RAG pipeline indexing a 600-page engineering manual uses fixed-size character chunking (500 characters). During retrieval, an LLM generates instructions for operating high-voltage machinery but misses critical hazard warnings printed immediately preceding the steps.
* **Options:**
  * A) Switch vector distance metric from Cosine Similarity to Euclidean distance.
  * B) Apply Semantic Chunking with a 15–20% Sliding Window Overlap.
  * C) Increase top-k retrieval parameter to k = 100.
  * D) Decrease the token embedding dimension from 1536 to 768.
* **Correct Answer:** **B**
* **Technical Explanation:** Fixed-size chunking blindly splits sentences and adjacent safety warnings across chunk borders. Sliding window token overlap ensures contextual continuity across boundaries.

### Question 4: Alphanumeric Code Retrieval in Vector Databases
**Scenario:** A RAG system designed for hardware inventory handles conceptual searches well (e.g., "cooling systems for high heat") but fails completely when technicians query exact alphanumeric product codes like `XG-9021-T`.
* **Options:**
  * A) Fine-tune the dense embedding model using RLHF.
  * B) Replace dense vectors entirely with a Random Forest index.
  * C) Implement a Hybrid Search architecture combining Dense Vector search with BM25/TF-IDF Sparse Keyword search.
  * D) Convert text documents into low-resolution JPEG images.
* **Correct Answer:** **C**
* **Technical Explanation:** Dense embeddings map semantic meanings, often scattering arbitrary alphanumeric strings in vector space. Sparse keyword search (BM25) excels at exact string and serial code matching.

* **Technical Explanation:** CoT forces the transformer to emit sequential intermediate tokens, giving attention layers compute steps to calculate intermediate arithmetic values before outputting the final number.

# CS Fundamentals: Core Exam Questions & Explanations

### Question 1: Usable Host Calculation in Subnetting
**Question:** Given the subnet mask `255.255.255.192`, how many usable host IP addresses are available in this subnet?
* **Options:**
  * A) 64
  * B) 62
  * C) 32
  * D) 30
* **Correct Answer:** **B**
* **Calculation:**
  * Last octet: $192 = 11000000_2$
  * Host bits ($H$) = number of zero bits = $6$.
  * Total IP addresses = $2^H = 2^6 = 64$.
  * Usable host IPs = $2^H - 2 = 64 - 2 = \mathbf{62}$ (subtract Network ID and Broadcast IP).

Question 3: SQL Aggregation Filtering (WHERE vs HAVING)
Question: Which of the following queries correctly filters departments where the average employee compensation is strictly greater than 75,000?

Options:

A) SELECT DeptID, AVG(Salary) FROM Emp WHERE AVG(Salary) > 75000 GROUP BY DeptID;

B) SELECT DeptID, AVG(Salary) FROM Emp GROUP BY DeptID HAVING AVG(Salary) > 75000;

C) SELECT DeptID, AVG(Salary) FROM Emp GROUP BY DeptID WHERE AVG(Salary) > 75000;

D) SELECT DeptID, AVG(Salary) FROM Emp HAVING AVG(Salary) > 75000;

Correct Answer: B

2. **Loop Boundaries:** Verify 0-indexed loops use `< n` instead of `<= n`. For adjacent pairs, use `< n - 1`.

9. **Recursion Base Cases:** Ensure base cases return concrete values and propagate error states (e.g., `-1`).

public List<List<Integer>> levelOrder(TreeNode root) {
    List<List<Integer>> res = new ArrayList<>();
    if (root == null) return res; // FIX 1: Guard clause

    Queue<TreeNode> q = new LinkedList<>();
    q.add(root);

    while (!q.isEmpty()) {
        int levelSize = q.size(); // FIX 2: Freeze queue size for the level

            TreeNode node = q.poll();
            level.add(node.val);

            if (node.left != null) q.add(node.left);
            if (node.right != null) q.add(node.right);
        }
        res.add(level);

    public boolean searchMatrix(int[][] matrix, int target) {
        if (matrix == null || matrix.length == 0 || matrix[0].length == 0) {
            return false;
        }

        int n = matrix.length;
        int m = matrix[0].length;

        // Start search at the top-right corner
        int row = 0;
        int col = m - 1; // 0-based boundary

        // Boundary checks require &&
        while (row < n && col >= 0) {
            if (matrix[row][col] == target) {
                return true;
            } else if (matrix[row][col] > target) {
                col--; // Target is smaller, eliminate current column
            } else {
                row++; // Target is larger, eliminate current row
            }
        }
        return false;
    }

public int jump(int[] nums) {
    if (nums == null || nums.length <= 1) return 0;

    int jumps = 0, currentEnd = 0, farthest = 0;

    // Loop strictly ends at n - 2 to prevent extra jump increment at destination
    for (int i = 0; i < nums.length - 1; i++) {
        farthest = Math.max(farthest, i + nums[i]);

        if (i == currentEnd) {
            jumps++;
            currentEnd = farthest;
            if (currentEnd >= nums.length - 1) break;

    }
    return jumps;

import java.util.*;

public int[][] merge(int[][] intervals) {
    if (intervals == null || intervals.length <= 1) return intervals;

    // Sort by start time ascending
    Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));

    List<int[]> merged = new ArrayList<>();
    int[] current = intervals[0];

    for (int i = 1; i < intervals.length; i++) {
        // Overlap exists if next start <= current end
        if (intervals[i][0] <= current[1]) {
            current[1] = Math.max(current[1], intervals[i][1]);
        } else {
            merged.add(current);
            current = intervals[i];
        }
    }
    merged.add(current); // Push trailing interval
    return merged.toArray(new int[merged.size()][]);
}

# Sliding Window Algorithmic Patterns

## Problem 1: Maximum Sum Harmonic Subarray ($\max - \min == 1$)

```cpp
#include <vector>
#include <map>
#include <algorithm>
using namespace std;

long long maxHarmonicSubarraySum(vector<int>& nums) {
    int n = nums.size();
    if (n < 2) return 0;

    map<int, int> windowMap; // Ordered map maintains sorted keys
    int left = 0;
    long long currentSum = 0;
    long long maxSum = 0;

    for (int right = 0; right < n; right++) {
        int val = nums[right];
        windowMap[val]++;
        currentSum += val;

        // Shrink window if difference between max key and min key > 1
        while (!windowMap.empty() && (windowMap.rbegin()->first - windowMap.begin()->first > 1)) {
            int leftVal = nums[left];
            windowMap[leftVal]--;
            if (windowMap[leftVal] == 0) {
                windowMap.erase(leftVal);
            }
            currentSum -= leftVal;
            left++;
        }

        // Valid harmonic window requires strictly max - min == 1 and at least 2 distinct keys
        if (windowMap.size() >= 2 && (windowMap.rbegin()->first - windowMap.begin()->first == 1)) {
            maxSum = max(maxSum, currentSum);
        }
    }
    return maxSum;
}
Problem 2: Sliding Window Maximum (O(N) Monotonic Deque)
Java
import java.util.*;

public int[] maxSlidingWindow(int[] nums, int k) {
    if (nums == null || k <= 0) return new int[0];
    int n = nums.length;
    int[] result = new int[n - k + 1];
    int resIdx = 0;

    Deque<Integer> deque = new ArrayDeque<>(); // Stores indices

    for (int i = 0; i < n; i++) {
        // Evict indices outside current window boundary
        while (!deque.isEmpty() && deque.peekFirst() <= i - k) {
            deque.pollFirst();
        }
        // Maintain monotonic decreasing order of values
        while (!deque.isEmpty() && nums[deque.peekLast()] <= nums[i]) {
            deque.pollLast();
        }
        deque.offerLast(i);

        if (i >= k - 1) {
            result[resIdx++] = nums[deque.peekFirst()];
        }
    }
    return result;
}

public class SubarraysWithXORk {
    public static int countSubarraysWithXOR(int[] nums, int k) {
        if (nums == null || nums.length == 0) return 0;

        Map<Integer, Integer> xorFreq = new HashMap<>();
        xorFreq.put(0, 1); // Base case initialization

        int xr = 0;
        int count = 0;

        for (int num : nums) {
            xr ^= num; // Running cumulative XOR
            int requiredPrefix = xr ^ k;

            if (xorFreq.containsKey(requiredPrefix)) {
                count += xorFreq.get(requiredPrefix);

            xorFreq.put(xr, xorFreq.getOrDefault(xr, 0) + 1);
        }
        return count;
    }
}

public int[] singleNumber(int[] nums) {

    for (int num : nums) overallXor ^= num;

    // Isolate rightmost set bit using long to avoid Integer.MIN_VALUE overflow
    long diffBit = overallXor & (-overallXor);

    int u1 = 0, u2 = 0;
    for (int num : nums) {
        if ((num & diffBit) != 0) {
            u1 ^= num; // Bucket 1
        } else {
            u2 ^= num; // Bucket 2
        }
    }

# Deductive Reasoning & Formal Syllogisms

### Question 1: Conversion of Particular Affirmatives
**Premise:** *"Some of the employees who work day shifts also work double shifts."*
* **Options:**
  * A) All employees who work day shifts also work double shifts.
  * B) Some employees who work day shifts do not work double shifts.
  * C) None of the employees who work day shifts work double shifts.
  * D) Some of the employees who work double shifts also work day shifts.
* **Correct Answer:** **D**
* **Logic:** The premise establishes non-empty intersection: $\text{Day} \cap \text{Double} \neq \emptyset$. "Some A are B" strictly guarantees "Some B are A". (Option B cannot be formally deduced because "All A are B" remains hypothetically possible).

**Premise:** *"All senior managers are required to attend the quarterly strategy meeting."*
* **Options:**

  * B) Anyone who is not a senior manager is not required to attend.

* **Logic:** Conditional form: $P \implies Q$ (Senior Manager $\implies$ Required). The contrapositive $\neg Q \implies \neg P$ (Not Required $\implies$ Not Senior Manager) is logically equivalent and always true.
